# 需求文档：企业数字化转型 · 多表数据分析决策平台

> 版本：v1.0（草稿，待评审）　|　定位：课程作业需求文档
> 核心理念：**把决策从"拍脑袋"变成"根据数据来决策"**（企业数字化转型）
> 基础：复用现有「CRM 自然语言数据库查询智能体」的架构，从 **1 张表 → 多张表**，从**查询 → 分析 → 建议**。

---

## 1. 背景与目标

### 1.1 背景

现有的 CRM AI Agent 已经做到：用户用中文提问 → AI 生成 SQL → 校验 → 真实执行 → 返回答案。
但它只是"查数据"。管理者真正需要的是**看完数据之后怎么办**。

本次作业要把系统从"查询工具"升级为"**决策助手**"：

```
数据（多张表） → 指标（客座率/毛利率/在岗率/流失风险） → 结论（员工画像） → 建议（打折/升职/加薪/淘汰）
```

### 1.2 目标

1. **多表支持**：系统能理解多张业务表之间的关联（如航班↔订单、员工↔考勤↔工资↔考评），跨表聚合分析。
2. **指标计算**：内置核心经营/人力指标，管理者一句话即可查询。
3. **决策建议**：系统不只给数字，还给"管理层行动建议"：
   - 航空：客座率只有 40%，参考近期运营数据与行业做法，建议打 xx 折；
   - 人力：员工"力争上游"，建议升职加薪 20%；风险员工进入关注/淘汰名单。
4. **看板（E2E 数字化）**：为管理层提供一页式数据看板（指标卡 + 趋势）。

### 1.3 价值主张

> 老板 / 管理层打开系统，用中文提问：
> 「为什么上座率这么低？」 → 系统给出客座率、趋势、原因线索，并建议**打折幅度与预期效果**。
> 「哪些人值得重点培养？哪些人在混日子？」 → 系统给出**人才画像 + 干预动作建议**。

## 4. 数据模型（新增多表）

### 4.1 航空子系统（2 张表）

```sql
-- 航班表
CREATE TABLE airline_flight_t (
  FLIGHT_ID       INT PRIMARY KEY,
  ROUTE           VARCHAR(50),      -- 航线，如 'HKG-PEK'
  AIRPLANE_MODEL  VARCHAR(50),      -- 机型
  TOTAL_SEATS     INT,              -- 总座位数（如 100）
  OPERATING_COST  DECIMAL(12,2),    -- 单次飞行运营成本（用于毛利率）
  FLIGHT_DATE     DATE,
  STATUS          VARCHAR(20)       -- scheduled / completed / cancelled
);

-- 订票表（1 航班 : N 订单）
CREATE TABLE airline_booking_t (
  ORDER_ID        INT PRIMARY KEY,
  FLIGHT_ID       INT,              -- FK → airline_flight_t
  PASSENGER_NAME  VARCHAR(50),
  TICKET_PRICE    DECIMAL(10,2),    -- 实际成交价（可体现打折）
  BOOKED_AT       DATETIME
);
```

### 4.2 人力子系统（4 张表）

```sql
-- 员工表
CREATE TABLE hr_employee_t (
  EMPLOYEE_ID      INT PRIMARY KEY,
  NAME             VARCHAR(50),
  GENDER           VARCHAR(10),
  DEPARTMENT_NAME  VARCHAR(50),
  POSITION         VARCHAR(50),
  HIRE_DATE        DATE,
  STATUS           VARCHAR(20),     -- active / resigned / blacklist
  PERFORMANCE_LEVEL VARCHAR(10)     -- A / B+ / B / C（当前绩效）
);

-- 考勤表（1 员工 : N 考勤记录）
CREATE TABLE hr_attendance_t (
  RECORD_ID   INT PRIMARY KEY,
  EMPLOYEE_ID INT,                  -- FK → hr_employee_t
  ATTEND_DATE DATE,
  STATUS      VARCHAR(20)           -- present / leave / late / absent
);

-- 工资表（1 员工 : N 月工资）
CREATE TABLE hr_salary_t (
  RECORD_ID     INT PRIMARY KEY,
  EMPLOYEE_ID   INT,                -- FK → hr_employee_t
  SALARY_MONTH  CHAR(7),            -- '2026-06'
  BASE_SALARY   DECIMAL(10,2),
  BONUS         DECIMAL(10,2),
  DEDUCTION     DECIMAL(10,2),
  NET_SALARY    DECIMAL(10,2)
);

-- 考评表（1 员工 : N 次考评）
CREATE TABLE hr_review_t (
  RECORD_ID    INT PRIMARY KEY,
  EMPLOYEE_ID  INT,                 -- FK → hr_employee_t
  REVIEW_DATE  DATE,
  SCORE_LEVEL  VARCHAR(5),          -- A / B+ / B / C
  SCORE        DECIMAL(4,1),        -- 0-100
  COMMENT      VARCHAR(200)
);
```

> 现有 `crm_employee_t` 可作为 `hr_employee_t` 的数据来源/演示替代，两者可共存。

## 5. 指标定义（给管理者和老板看的）

### 5.1 航空运营指标

| 指标 | 公式 | 示例 |
| --- | --- | --- |
| 客座率 | 实际乘坐人数 ÷ 总座位数 × 100% | 40 / 100 = **40%** |
| 上座人数 | COUNT(某航班的订票记录) | 40 人 |
| 平均票价 | SUM(实际成交价) ÷ 订单数 | 800 元 |
| 总收入 | SUM(TICKET_PRICE) | 32,000 元 |
| 总成本 | SUM(OPERATING_COST)（关联航班） | 25,000 元 |
| **毛利率** | (收入 − 成本) ÷ 收入 × 100% | (32000−25000)/32000 = **21.9%** |
| 打折力度 | (基准价 − 成交价) ÷ 基准价 | −30% |

### 5.2 人力分析指标

| 指标 | 公式 | 说明 |
| --- | --- | --- |
| 在岗率 | 出勤天数 ÷ 应出勤天数 × 100% | 越高越稳定 |
| 请假率 | 请假天数 ÷ 应出勤天数 × 100% | 异常升高 = 风险信号 |
| 迟到/旷工率 | 迟到或旷工天数 ÷ 应出勤天数 | 纪律性 |
| 绩效分布 | 按考评等级统计占比 | A / B+ / B / C |
| 工资均值/涨幅 | AVG / (本期−上期)÷上期 | 激励与公平性 |
| 离职率 | 期间离职人数 ÷ 期初人数 | 团队稳定性 |
| **流失风险分** | 规则评分（见 6.3） | 0–100，越高越危险 |

## 6. 功能需求

### 6.1 通用能力（复用现有，不重造）

| 能力 | 说明 | 来源 |
| --- | --- | --- |
| 自然语言 → SQL | 中文提问，LLM 生成 SQL | 复用，升级为**多表** |
| SQL 安全校验 | Parser + 黑名单 + 表名白名单 | 复用 |
| 真实执行 | 答案必须来自数据库 | 复用 |
| 数据库 Agent（工具循环） | 多步分析（取样→聚合→结论） | 复用，补充建议输出 |
| Excel 导出/导入 | 过滤弹窗 + 批量导入 | 复用 |
| 查询历史 | Question/SQL/Answer | 复用 |
| RBAC + 登录 | admin / user | 复用 |
| 看板 | 指标卡 + 图表（前端新增图表） | **新增** |
| 建议引擎 | 结构化建议输出 | **新增** |

### 6.2 航空子系统（练手）

FR-A1　按航班/航线查询**客座率**（跨 `airline_booking_t` 与 `airline_flight_t` JOIN）。
FR-A2　查询**毛利率**（收入 − 成本，跨表聚合）。
FR-A3　查询近 N 个月**客座率趋势**、**打折与上座关系**（数据分析的威力：打折是否真的带来更多人）。
FR-A4　**决策建议**：系统综合「最近 3 个月运营数据 + 当前客座率（如 40%）」，输出结构化建议：
```json
{
  "问题": "客座率仅 40%，远低于盈亏平衡点",
  "建议": "建议整体票价下调 30%（8.5 折→7 折区间）",
  "依据": "近 3 个月数据显示：票价每下调 10%，上座率提升约 8%",
  "预期效果": "客座率预计提升至 55-60%",
  "风险": "淡季效果可能打折，建议小范围试销 2 周"
}
```

### 6.3 人力子系统（核心）

FR-B1　**员工画像**：输入员工姓名，输出多维度画像：
- 绩效：历史考评等级趋势（A/B+/B/C）
- 考勤：在岗率、请假率、迟到/旷工率
- 薪酬：工资水平、涨幅、与部门均值对比
- 综合标签：**力争上游 / 稳步成长 / 有待观察 / 流失风险 / 边缘化**

FR-B2　**流失风险预测（规则评分）**：
| 风险信号 | 加分 |
| --- | --- |
| 绩效连续 2 期下滑（B→C） | +20 |
| 请假率 > 10% | +15 |
| 旷工 ≥ 2 次 | +25 |
| 工资低于部门均值 20% 且 1 年未调薪 | +20 |
| 长期未晋升（>3 年无升职记录） | +10 |
| 绩效优秀（A/B+）但薪酬偏低 | +15 |
| ≥60 = 高风险，40–59 = 中风险，<40 = 低风险 | |

FR-B3　**干预动作建议**（对每个员工输出 1 个建议动作）：
| 动作 | 适用画像 | 参考比例 |
| --- | --- | --- |
| **升**：升职加薪 20% | 力争上游（高绩效、高在岗、潜力大） | 20% |
| **育**：不升职但加薪 + 授予更大权力 | 骨干、绩效好但岗位无空缺 | 10% |
| **留**：不升职不加薪，维持留任 | 中坚力量、绩效稳定 | 50% |
| **裁**：进入黑名单，计划淘汰 | 长期低绩效 + 高流失风险 + 纪律差 | 20% |

FR-B4　**人力看板**：公司级/部门级一页看板：
- 员工总数、在岗率、请假率、离职率、绩效分布
- 风险名单 Top10、建议动作分布（升/育/留/裁）
- 部门对比（哪个部门请假率最高？哪个部门绩效最好？）

FR-B5　NL 问题示例：
- 「客座率最低的 5 条航线是哪几条？」（航空）
- 「技术部最近 3 个月在岗率是多少？」
- 「工资低于部门平均值 20% 的员工有哪些？」
- 「李四是什么人才画像？建议怎么处理？」
- 「给我一个 10 人风险名单，按风险分排序」

## 7. AI Agent 能力增强

### 7.1 多表 Schema

- 系统提示词注入**所有表**的 Schema（含外键关系说明），LLM 生成 SQL 时自动使用 JOIN。
- 表名白名单覆盖全部业务表；系统表仍禁止访问。

### 7.2 工具扩展

在现有 `execute_sql` 工具基础上，为决策建议增加**规则工具**：

| 工具 | 说明 |
| --- | --- |
| `execute_sql` | 只读 SELECT，支持多表 JOIN（现有） |
| `get_metric`（可选） | 按名称取内置指标（客座率/在岗率/风险分） |
| `suggest_action` | 输入员工/航线画像，输出结构化建议（调后端规则引擎） |

> 决策建议尽量用**后端规则引擎**（可解释、稳定、不消耗额外 token），LLM 负责组织语言与上下文。

### 7.3 建议输出结构

建议以 JSON 结构化输出，前端以「建议卡片」展示（与现有「查看 SQL」并列）。
